--- layout: alternative tool: bruno title: A Bruno alternative for gRPC, SignalR and MQTT — Bowire description: Bowire vs. Bruno — when each fits, where they differ feature by feature, and how to import a Bruno collection folder, .bru or OpenCollection YAML. Local-first, Apache 2.0. lede: Bruno keeps collections as plain files in git. Bowire shares the local-first stance and adds discovery, record & replay, mocks and many more protocols. ---

Bowire imports a Bruno collection folder directly, in both of Bruno's formats: .bru files and OpenCollection YAML (the default since Bruno 3.1). Right-click Collections in the Workspaces tree and choose Import folder…, or run bowire import path/to/collection.

  • What comes across: requests in their folders and seq order, with path parameters filled in; collection and folder headers and auth, including auth: inherit; environments, with OpenCollection's extends resolved.
  • What the import report names: scripts, tests and assertions; secret variables, whose values never leave Bruno's local storage; auth types to set on the Bowire environment; gRPC and WebSocket requests.
  • Or skip the import and point Bowire at the running service — discovery covers OpenAPI, gRPC and GraphQL.

The migration guide lists what maps one-to-one, what changes shape, and what has no equivalent.
