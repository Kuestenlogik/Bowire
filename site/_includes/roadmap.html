On course

A short look at what just landed — and what’s on the way.

The map you can read v2.7

The map widget stops being a scatter of dots: trajectory LineStrings join an entity’s frames into a path, per-entity grouping tells thirteen contacts apart by their own identity rather than merging them, and a time cursor with playback rewinds a stream you already collected. Alongside it, the gRPC plugin reaches a server with Server Reflection switched off — the state Bowire’s own scanner recommends — and the scanner learns three failures that survive every “is it public?” check.

Multi-tenancy v2.6

One Bowire, several authenticated passengers. Point it at any OIDC provider and every identity gets its own slot on disk — workspaces, recordings, collections, plugin settings — with SCIM 2.0 provisioning keeping the roster in step and per-user plugins so one person’s install is not everybody’s.

The CI pillar v2.5

Design-time lint reads the discovered surface for design smells — PII in responses, unbounded collections, missing versioning. Latency gates and a contract matrix turn a run into a pass/fail a pipeline can act on, one rollup puts every signal on one page, and the workbench arrives in your editor as a VS Code extension.

The Dev pillar v2.4

Mock-from-schema without a recording, the schema-watch diff that shows what moved in your API while you were away, side-by-side service compare across two versions or deployments, the correlated multi-protocol timeline for recordings — and CLI / UI / MCP parity, so every capability is reachable from all three.

The Security pillar v2.3

bowire scan runs the full OWASP API Security Top 10 — 10/10, with protocol-specific probes for GraphQL, gRPC, WebSocket, SSE, MQTT and MCP — plus an opt-in active attack tier and a complete out-of-band (OAST) chain with a self-hosted bowire oast serve catcher. The Monitoring rail runs saved recordings as scheduled health probes with Slack / PagerDuty / OTLP signalers.

Now: workbench UX polish v2.8

Underway. The freeform builder already landed — schema-free ad-hoc REST, URL and verb and body, for the endpoint that has no schema to discover. Still ahead: a header library of named, scoped, toggleable header sets; i18n with German and English catalogues; a within-tab and cross-tab split layout; and a visual shelf for dragging fragments between surfaces.
2

MCP completion + agent hub v2.9

The remaining MCP tools and adapter modes, server-side notifications through the SDK’s handlers, and the agent hub — embedded Bowire instances registering with a central hub so an agent can find them.
3

Cleanups + breaking-change cuts v3.0

The version where deprecated shapes come out rather than accumulate — among them the ${name} variable syntax that {{name}} replaced.

Nothing on this list is a commitment — Bowire is built in the open, and priorities shift with what users actually hit in practice. If something here matters to you, file an issue or start a discussion.
